100M1S 디자인 요구사항 정의서 1차 (DRD-v1)

본 문서는 100M1S의 디자인 시스템과 UI/UX 명세를 통합한 1차 산출물입니다. 기능 요구사항 정의서와 짝을 이루며, 시각·UI 레이어에 한정합니다.

§0. 메타

0.1 범위

  • 포함: 브랜드 정체성, UI 컴포넌트, 페이지·플로우(시각), 반응형·접근성, 마이크로 인터랙션, 시각 일관성 룰, 우선순위.
  • 제외 (짝 문서로 위임): 기능 동작, 데이터 모델, API/DB 스키마, 파이프라인 정책, 알고리즘 룰.

0.2 대상 서비스

코드 제품 시각 적용 범위
P000 100M1S 회사 홈페이지 (news.html) 본 1차 핵심 — 명세 90% 적용처
P001 경매 분석 기획. 시각 명세 미수립
P002 PM320 POC UI v1~v18 사료 보존. 본격 시각은 후속 사이클
P003 소마타 기획. 시각 명세 미수립
P004 글래스박스 기획. 시각 명세 미수립

0.3 1초 본질 (전 화면 공통)

  1. "확정만 + 오늘/내일만" — 헤더에는 확정 정보·오늘/내일 외 시점 금지. 추정은 보조 영역(사유 박스·툴팁).
  2. "한 화면 = 하나의 메시지" — 둘을 동시에 말하면 0이 전달됩니다.
  3. "숫자보다 의미" — "거래대금 7,122억" < "거래대금 1위".

0.4 워크스루 의무

모든 시각·UI 변경은 사전·사후 워크스루 양면 의무.
- 사전: 플로우 확정 전 UX 텍스트 4축 + 시각 7축 검토.
- 사후: 코드 작성 후 라이브 DOM·실데이터·캐시 3축 검증.
- 위반 시 결함 등재.

0.5 디자인-구현 동기화 의무

시각 컴포넌트 코드 수정 시 디자인 명세 동시 갱신 의무. 정합 컨트랙트 통과 후 commit. 본 문서와 모듈별 명세는 본문 갱신 시 cross-link 갱신.

§1. 브랜드 정체성

1.1 회사명·태그라인

  • 회사명: 100M1S (One Hundred Million, One Step)
  • 태그라인 (확정): 100 Million, 1 Step / 1억, 한 걸음에
  • 헤더 정체성 칩: 100M1S News uppercase 골드 + accent span 한글 강조 (예: "시장은 매 시간 새로 쓰인다").

1.2 로고 (미결)

  • 시안 v1→v4 진행. 38·39 페어(Serpenti S 영감 + 낙수천석) 유력 후보. 현재 미결정 상태.
  • 향후 결정 시 본 §1.2 갱신 + 모든 정체성 톤(§1.4 컬러)과 그라데이션(§4) 재정합 검증 의무.

1.3 컬러 시스템 (확정)

1.3.1 한국 증시 상승·하락 색 (단일 SSOT)

의미 hex 적용처
상승 (양봉) #C53939 mini-candle, sparkline, section-title.up, .pct.up 계열
하락 (음봉) #1958C7 mini-candle, sparkline, section-title.down, .pct.down 계열
동가 (flat) #94A3B8 mini-candle 동가, 추세 칩 중립

P0 결정 (회귀 봉쇄): 상승·하락 hex는 단일 SSOT. 후속 회귀 fix 사이클에서 통일 의무.

단일 isUp 판정 룰: mini-candle은 close > open, sparkline·텍스트 칩은 changePct >= 0. 컴포넌트별 의미에 따른 isUp 판정은 허용하되, 적용 hex 팔레트는 단일 SSOT.

1.3.2 햇살 톤 (100M1S 정체성)

토큰 hex 적용처
Sun-50 #FFF9E8 toppick·grade-badge 배경
Sun-100 #FFF4D1 kiwoom-block·toss-cal 배경
Sun-500 #E8C063 macro-chip 액센트, 골드 라인

1.3.3 액센트

  • Toss Blue #0064FF — 링크·확정 CTA. WCAG AA 이상 대비.

1.3.4 그레이 토큰 SSOT

--g04: rgba(0,0,0,0.04);
--g08: rgba(0,0,0,0.08);
--g40: rgba(0,0,0,0.4);
--g60: rgba(0,0,0,0.6);
--g80: rgba(0,0,0,0.8);
  • 텍스트 영역 대비 룰: 배경이 --g04~--g08이면 글자는 --g60~--g80 또는 햇살 톤. WCAG AA(4.5:1) 의무.
  • 즉흥 hex(#999/#ccc) 금지.

1.4 타이포

  • 본문: Inter + Pretendard (Toss 친근 산세리프).
  • 헤더: SF Pro · Pretendard 시스템 폰트.
  • 8px 그리드 정렬. 본문 폭 1100px ±. 65ch는 갑갑 — 금지.
  • 최소 폰트 12px. 미만 = 가독성 위반.

1.5 톤보이스

  • Toss/Apple 감성 + 100M1S 햇살 정체성 확정.
  • Stripe Press × Linear × Are.na 미니멀리즘 톤은 폐기 (시각 변화 0 + 갑갑함).
  • 일률 미니멀리즘 = 햇살 정체성 손실. 체감 변화 + 정체성 정합 동시 검증 의무.

§2. UI 컴포넌트 (시각 SSOT)

2.1 종목 카드

  • 주체: .stock-card (/news).
  • 구성: 종목명 + 6자리 티커 + 시제 칩(§2.4) + 단계 플로우(§2.3) + 효과 배지(§2.6) + mini-candle(§2.5) + 뉴스 인사이트 + 공유 링크.
  • 공유 URL: #stock-{6자리 ticker} (한글 이름 금지).
  • 배지 상세박스: 3단 구조 — ① 현재 상태 / ② 다음 예고(조건+기간) / ③ 인사이트.

2.2 뉴스 카드

  • 헤더 한 줄 + 본문 1~2줄 + 출처 + 시간.
  • 출처 칩 = 회색 톤, 테마 칩 = 보라 톤 (색조 통일).
  • 카드 3중 이상 중첩 금지.

2.3 단계 플로우 (Stage Flow)

  • 본질: 헤더 = 확정 + 오늘/내일만. 추정·"X일 후" enum 폐기.
  • 노드 4축 위계:
    | 시제 | 시각 표현 |
    |------|---------|
    | 과거(완료) | 회색 노드 |
    | 현재(진행) | 실선 노드 (이번 노드는 강조) |
    | 예고(strict) | 얇은 점선 |
    | 예고(loose)·추정 | 굵은 점선 |
  • 박스 prefix 제거: "예고:"/"현재:" 접두어 제거. 박스 자체가 의미 운반.
  • predicted strict 미충족 그래프 비노출: 데이터 SSOT 부재 시 노출 0건.

2.4 시제 칩 (Tense Chip)

  • 5개 enum: 오늘 / 내일 / 완료 / 진행 중 / 내일 가능(strict 충족 시).
  • "X일 후"·"X~Y일" 범위 시점 금지.
  • 폰트 11~12px. border-radius 9999px (pill).
  • 색조: 햇살 톤 또는 액센트 톤 — 의미별 단일 매핑.

2.5 mini-candle (20영업일)

  • 컴포넌트: SVG inline IIFE.
  • 색 룰: close > open → #C53939 (양봉) / close < open → #1958C7 (음봉) / close = open → #94A3B8 (동가).
  • 단일 isUp 분기 SSOT.
  • 폭·높이·spacing 8px 그리드.

2.6 효과 배지 (Effect Badge)

  • 헤더 시점 enum: today / tomorrow 만.
  • 본질: 헤더 = 효과별 + 시점 (신용불가/거래정지/단일가 × 오늘/내일).
  • 사유 박스: 1줄 단순. 거래정지·단일가 일정 미언급(1차원 정보 X). KRX 단계 + 증권사 사유 통합.
  • 단기과열 예고: D+0 효과 부재 정합 → 헤더 0건. 사유 박스만 노출.
  • 거짓 기능 위험 회피: 데이터 SSOT 인프라 부재 시 강행 금지. 데이터 인프라 갖춰진 후 부활.

2.7 그래프 박스 (Stage Graph Box)

  • 그래프 박스 내부 = 날짜 + 자동효과. predicted only 위계 분리.
  • current "예고" 노드 박스 날짜 = view_date 단독. 박스/폰트 점진 축소.

2.8 임계가격 표시

  • entry threshold + window + assumption 3종 항상 동반. 단독 가격 노출 금지.

2.9 시장경보·단일가 배지

  • 시장경보·단일가 뱃지 통합. 박스 화살표 제거.

2.10 신용불가 사유 박스

  • KRX 단계 + 증권사 사유 통합. 그래프 박스 제거 후 사유 박스 단독.

2.11 정체성 칩 (헤더)

  • 100M1S News uppercase 골드 + accent span 한글 강조.
  • 햇살 톤 그라데이션 보존 (정체성 그라데이션 허용 영역).

§3. 페이지·플로우

3.1 메인 (/)

  • Above the fold = 회사 태그라인 + 핵심 CTA 1개. 모바일 일관.

3.2 /news (P000 핵심 화면, 명세 90%)

  • 상단: 100M1S News 헤더 정체성 칩 + 시각 ("마지막 업데이트 15:32" 명시. "실시간" 표현 금지).
  • 본문: 종목 카드(§2.1) 리스트 + 거래대금 추이(20영업일) + 테마 트렌드(§3.3) + LUT 차트 + 테마 트리(§3.4).
  • 푸터: 페이지 1회 'ⓘ투자판단 권고 아님' (footer 매 카드 반복 폐기).
  • 공유: 공유 토스트 + URL hash → #stock-{ticker} 6자리.
  • PRE_MARKET 분기: 세션 단위 차트 = 빈 상태 + stale 라벨. trend window = 미적용.

3.3 테마 트렌드 / LUT 차트 (20영업일)

  • viewport 동적 legend sync. cap 폐기 — 활성 root 모두 표시.
  • viewport mask: .trend-scroll-area max-width: 864px (desktop), 435px (mobile@880-). SVG 20일, viewport 7/10일 mask.
  • legend 가로 스크롤(모바일). WCAG 44×44 터치 타겟.

3.4 테마 트리 (계층 트리맵)

  • PRE_MARKET 분기 빈 상태 + stale 라벨 자연 봉쇄(정적 header 신뢰).
  • 테마칩 = 보라 톤 단일. 표준 테마 사전 SSOT 정합.

3.5 종목 상세

  • 본 1차에서는 별도 페이지 없음. 종목 카드 expand로 통합.
  • 후속 사이클에서 상세 페이지 분리 검토.

3.6 종목 anchor 네비게이션

  • 전역 등록 + capture click handler. #stock-{ticker} hash → scroll.

3.7 (신규) 요구사항 뷰어 페이지

  • 본 디자인 요구사항 정의서를 사이트 내 뷰어로 노출하는 페이지. 본 1차에서는 시각 명세 미수립. 후속 사이클에서 갱신.

§4. 그라데이션 정책

4.1 허용 (의미 OR 정체성)

  • 의미: 가격 스펙트럼(.stock-range 청→적), 추세 양극.
  • 정체성: 햇살 톤(§1.3.2) — toppick/grade/macro/kiwoom/toss-cal.

4.2 금지 (장식만)

  • 빈 차트 패턴, fade overlay 단순 장식.
  • 햇살 톤 외 색상 그라데이션.
  • 액센트 색 그라데이션.

§5. 반응형·접근성

5.1 모바일 = 데스크탑 동일 정보 (필수 룰)

  • 폰트 축소로 해결, 정보 숨김 금지.
  • 본 룰 위반은 시각 결함이자 데이터 신뢰성 결함.

5.2 브레이크포인트

  • @media (max-width: 880px) — 모바일.
  • viewport mask: desktop 864px / mobile 435px.

5.3 터치 타겟

  • 최소 44×44pt (Apple HIG, WCAG 44×44).
  • 인터랙티브 요소 전부 검증 의무.

5.4 sticky 헤더

  • /news 상단 정체성 칩 + 갱신 시각 sticky. iOS Safari 호환.

5.5 다크모드

  • @media (prefers-color-scheme: dark) 자동 반전.
  • 햇살 톤은 darken 톤 매핑(후속 사이클 정의).

5.6 접근성 (a11y)

  • WCAG AA 4.5:1 이상 대비 의무.
  • focus-visible 명시 의무.
  • alt·aria-label 모든 SVG/아이콘.
  • 이모지 아이콘 금지(픽셀 깨짐 + 멀티플랫폼 부정합) — SVG inline 의무.

§6. 마이크로 인터랙션

6.1 트랜지션 토큰

  • 200~300ms, cubic-bezier(0.16, 1, 0.3, 1).
  • 호버 미묘(ghost outlined 정합).
  • focus-visible 명시.

6.2 공유 토스트

  • 'URL 복사됨' 토스트 1.5s. 햇살 톤 배경.

6.3 expand·collapse

  • 종목 카드 expand 자연 height. easing 동일 토큰.

§7. 일관성 룰 — 시각 7축 + UX 4축

7.1 시각 일관성 7축 (신규 BEM·컴포넌트 도입 시 의무)

  1. 모양 — border-radius·padding·font-size·font-weight 동일 카테고리 정합.
  2. 색조 — 동일 의미 카테고리 동일 팔레트 (효과 배지 = sev-*, 출처 칩 = 회색, 테마 칩 = 보라).
  3. size — 동일 영역 폰트 단계 ≤ 3개.
  4. 상호작용 — transition·cursor·focus-visible 일관.
  5. 누적 회귀 — 신규 BEM 추가 시 기존 정합 + CSS specificity + visual diff.
  6. 변형 위계 — 솔리드 vs ghost/outlined/text. 평탄화 회피.
  7. 이모지 vs SVG — 신규 아이콘 SVG inline. 이모지는 사용자 텍스트(인사이트)만.

7.2 UX 텍스트 4축 (사용자 노출 텍스트 명세 시 의무)

  1. 의미 명확성 — 1초 인지 가능?
  2. 확정성 — 헤더는 확정만, 추정은 보조 영역.
  3. 매매 직결성 — 사용자 매매 결정에 직접 도움?
  4. 시점 명료성 — 오늘/내일/구체 날짜 명시.

7.3 단일 isUp + 단일 hex SSOT

  • 컴포넌트별 isUp 판정 분기(mini-candle = close>open, 텍스트 = pct>=0)는 허용.
  • hex 팔레트는 단일 SSOT (§1.3.1).
  • 신규 컴포넌트 추가 시 본 SSOT 참조 의무.

7.4 거짓 충실성 차단

  • 추정 + 확정 시점 결합 금지 ("거래정지(2일 후)" 형태).
  • 모호 라벨 금지 ("지정 조건 상세"/"신뢰도"/"단계 진행").
  • 3축 검증: 코드 grep + 실데이터 매트릭스 + DOM 잔존.

7.5 부분 패치 자기기만 회피

  • 동일 컴포넌트 부분 패치 3회 도달 = 강제 본질 재설계.
  • 컨테이너 default = "박스" 회피. 박스/표/list/grid/inline-flex 중 데이터 type에 적합한 것 명시.
