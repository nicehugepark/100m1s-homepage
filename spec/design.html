100M1S 디자인 요구사항 정의서 1차 (DRD-v1)

본 문서 = 4/5~5/13 누적 디자인 결정·UI/UX 명세를 흡수·통합한 디자인 요구사항 정의서.
기능 요구사항 정의서(REQ-001, planning-lead 작성)와 짝. 본 문서는 시각·UI 레이어에 한정하고, 기능·백엔드·파이프라인·DB는 REQ-001에 위임한다. 모듈 SSOT인 DSN-arch-{frontend|backend|pipeline|infra} 4건은 supersede하지 않고 preserve — 본 문서는 시각·UI SSOT, arch-* 는 코드 모듈 SSOT.

[design-lead] 응답 시각: 2026-05-13 (수) 18:55:00 KST

§0. 메타 (REQ-001 짝)

0.1 범위

  • 포함: 브랜드 정체성, UI 컴포넌트, 페이지·플로우(시각), 반응형·접근성, 마이크로 인터랙션, 시각 일관성 룰, 우선순위, supersedes/preserves.
  • 제외 (REQ-001로 위임): 기능 동작, 데이터 모델, API/DB 스키마, 파이프라인 정책, 알고리즘 룰.

0.2 대상 서비스

코드 제품 시각 적용 범위
P000 100M1S 회사 홈페이지 (news.html) 본 1차 핵심 — 90% 명세 적용처
P001 경매 분석 기획. 시각 명세 미수립
P002 PM320 POC UI v1~v18 사료 보존. 본격 시각은 후속 사이클
P003 소마타 기획. 시각 명세 미수립
P004 글래스박스 기획. 시각 명세 미수립
P005 Trade Cockpit (내부) 외부 노출 0. 시각 명세 비대상
LAB 작전주 PPT (lab/*) §6 트랙 별도 — 비공개 PPT

0.3 1초 본질 (전 화면 공통)

  1. "확정만 + 오늘/내일만" — 헤더에는 확정 정보·오늘/내일 외 시점 금지. 추정은 보조 영역(사유 박스·툴팁).
  2. "한 화면 = 하나의 메시지" — 둘을 동시에 말하면 0이 전달된다.
  3. "숫자보다 의미" — "거래대금 7,122억" < "거래대금 1위".

0.4 워크스루 의무 (FLR-20260406-PRC-002 recurring 봉쇄)

모든 시각·UI 변경은 사전·사후 워크스루 양면 의무.
- 사전: 플로우 확정 전 §6 UX 텍스트 4축 + §7 시각 7축 검토.
- 사후: 코드 작성 후 라이브 DOM·실데이터·캐시 3축 검증.
- 위반 시 FLR 자동 등재. 본 룰은 5건 이상 recurring 누적 사고.

0.5 DSN-arch-* 동기화 의무 (DOC-20260507-FLR-004 봉쇄)

시각 컴포넌트 코드 수정 시 DSN-arch-frontend 동시 갱신 의무. bash scripts/qa/run-qa.sh design-doc-sync PASS 후 commit. 본 문서(DRD-v1)와 arch-frontend는 본문 갱신 시 cross-link 갱신.

1.3 컬러 시스템 (확정)

1.3.1 한국 증시 상승·하락 색 (단일 SSOT — 본 1차 critical 결정)

의미 hex 적용처
상승 (양봉) #C53939 mini-candle, sparkline, section-title.up, stock-pct.up, kiwoom-pct.up, cal-credit-badge, .pos, .v33.trig
하락 (음봉) #1958C7 mini-candle, sparkline, section-title.down, stock-pct.down, kiwoom-pct.down, .neg, .v33.safe
동가 (flat) #94A3B8 mini-candle 동가, 추세 칩 중립

🔴 P0 결정 (회귀 봉쇄): 상승·하락 hex는 단일 SSOT. 코드 잔재로 발견된 #E03131(toss 톤 적색)·#1971C2(toss 톤 청색)은 utils.js sparkline 영역에서 발견된 회귀 — 본 1차 명세로 #C53939/#1958C7로 통일 의무. 후속 fix 사이클은 REQ-001에서 발주.

🔴 단일 isUp 판정 룰: mini-candle은 close > open, sparkline·텍스트 칩은 changePct >= 0로 분기 흩어짐 발견. 본 1차 명세는 컴포넌트별 의미에 따른 isUp 판정은 허용하되, 적용 hex 팔레트는 단일 SSOT. (값 0인 경우 mini-candle = 동가 #94A3B8, 텍스트 칩 = 상승 #C53939 정합).

§2. UI 컴포넌트 (시각 SSOT)

2.1 종목 카드

  • 주체: .stock-card (news.html /news).
  • 구성: 종목명 + 6자리 티커 + 시제 칩(§2.4) + 단계 플로우(§2.3) + 효과 배지(§2.6) + mini-candle(§2.5) + 뉴스 인사이트 + 공유 링크.
  • 공유 URL: #stock-{6자리 ticker} (한글 이름 금지 — feedback_share_url_ticker_only).
  • 배지 상세박스: 3단 구조 — ① 현재 상태 / ② 다음 예고(조건+기간) / ③ 인사이트. (DOC-20260422-DSN-001 v7.5 흡수).

2.2 뉴스 카드

  • 헤더 한 줄 + 본문 1~2줄 + 출처 + 시간.
  • 출처 칩 = 회색 톤, 테마 칩 = 보라 톤 (§7.2 색조 통일).
  • 카드 3중 이상 중첩 금지 (§10).

2.3 단계 플로우 (Stage Flow)

  • v9.8.1 본질 (DSN-010 흡수): 헤더 = 확정 + 오늘/내일만. 추정·"X일 후" enum(in_2_days/in_3_5_days/tomorrow_maybe) 폐기.
  • 노드 4축 위계 (v9.3 흡수):
    | 시제 | 시각 표현 |
    |------|---------|
    | 과거(완료) | 회색 노드 |
    | 현재(진행) | 실선 노드 (이번 노드는 강조) |

§7. 일관성 룰 — 시각 7축 + UX 4축

7.1 시각 일관성 7축 (신규 BEM·컴포넌트 도입 시 의무)

  1. 모양 — border-radius·padding·font-size·font-weight 동일 카테고리 정합.

  4. 상호작용 — transition·cursor·focus-visible 일관.
  5. 누적 회귀 — 신규 BEM 추가 시 기존 정합 + CSS specificity + visual diff.
  6. 변형 위계 — 솔리드 vs ghost/outlined/text. 평탄화 회피.
  7. 이모지 vs SVG — 신규 아이콘 SVG inline. 이모지는 사용자 텍스트(인사이트)만.
